# Execution Framework audit — low-impact WAS + RDM

**Scope:** The recent recipient/bridge fixes, triggered synthetic proof,
opt-in Responses API mock proof, subsequent integration recommendations, and
the new on-demand CLI workflow. This is a scoped implementation audit, not
certification of every subsystem in the repository.

## Verified facts

- The published browser delivery and restart tests, synthetic manager-worker
  test, and local API mock test do **not** prove live ChatGPT website operation.
- The optional API proof is not free in live mode and has not been run with a
  real API key.
- Codex CLI is installed and signed in on Galactus, but it is **not** the
  accepted execution method; invoking it would consume its applicable usage
  allowance. No Codex command was invoked to do implementation work in this
  pass.
- An attempted standalone Ollama download was stopped in an earlier pass;
  the partial archive was removed. The binary is absent.
- The new RDM workflow uses the existing `DurableStore`; a real local
  syntax and repository verification task was claimed, executed, completed,
  and read back from a separate CLI invocation. Only short-lived Python
  processes were needed.

## Material corrections

1. **Architecture drift:** Previous paid-API, Codex, and local-model suggestions
   contradict the operator's actual constraints. The accepted path is now
   **existing ChatGPT conversation + Web Agent Swarm durable task state +
   Remote Desktop Commander computer execution**, with no extra inference
   engine or unattended service. Optional legacy proofs remain clearly
   outside the approved path; no need to delete working history.
2. **CLI workflow gap:** `task-create` existed, but an on-demand RDM operator
   lacked `task-list`, `task-claim`, `task-heartbeat`, and `task-release`
   on the CLI. These now wrap the existing state methods without duplicating
   scheduler, browser, or lease logic. New tests cover ownership,
   dependency blocking, invalid results, and terminal failure.
3. **Evidence overclaim risk:** Previous POCs used synthetic browser sessions
   or a mock API. Neither certifies ChatGPT message/response extraction,
   autonomous multi-chat coordination, or six-worker operation. Documentation
   now distinguishes those from the real computer-tool task check.
4. **Usage/cost precision:** No new software subscription or API billing is
   required for the RDM workflow. This does not mean ChatGPT reasoning has
   unlimited/free token allowance; existing plan usage rules still apply.

## Unresolved boundary

OpenAI's consumer Terms prohibit automatically or programmatically extracting
ChatGPT Output. Triggering such extraction externally does not by itself
make it an authorized integration. The existing browser extension code must
not be treated as approved for live ChatGPT output collection. Any future
multi-session automation requires a supported/authorized data path first.

## Verdict

- **GREEN WITH BOUNDED CORRECTION** for the local, on-demand, one-manager /
  RDM-executor approach.
- **BLOCKED** for a fully unattended, zero-extra-cost six-ChatGPT-session
  swarm: there is no verified authorized output-return path.

**Next action:** use the lightweight task CLI for user-directed computer work.
Do not launch Codex, a paid API, a local model, six browser workers, or a
background scheduler merely to route tasks. Reassess only on concrete unmet
requirements or new platform authorization.
